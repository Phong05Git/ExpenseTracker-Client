HOW TO TRACK
============================================================
[+] = Completed and verified with evidence.
[ ] = Not completed, not started, or not yet verified.
[~] = In progress (use only when a task is actively being worked on).

Rules:
1. Mark [+] only after the implementation/build/test result is confirmed.
2. "Code written" is not the same as "built"; "built" is not the same as "tested".
3. Keep evidence: changed files, commands, test cases, output, screenshots/logs.
4. At the start of a resumed task, read this checklist and verify the latest source.
5. Do not assume this checklist proves the current working tree has not changed.
6. Update this file after each completed milestone.

A. PROJECT SCOPE AND FIXED CONSTRAINTS
============================================================
[+] Phase 2 has three main directions:
    - Admin Management System.
    - Move Backend and PostgreSQL from Render to Localhost; manage TLS
      certificates and Android Certificate Pinning.
    - Local AI financial chatbot and AI-specific security controls.

[+] Phase 1 remains the baseline; do not rewrite stable existing features.
[+] Current stack baseline: Android Java 17; ASP.NET Core 10;
    EF Core 10; PostgreSQL; Android MVVM + Clean Architecture;
    Backend layered architecture.
[+] Backend must enforce authentication, authorization and data ownership.
[+] Never trust a UserId supplied by Android or extracted from a prompt.
[+] Local LLM must not connect directly to PostgreSQL and must not receive
    database credentials.
[+] Backend retrieves and scopes financial data before preparing AI context.
[+] Prompt instructions/keyword filters are not authorization controls.
[+] Do not store secrets, passwords, tokens, connection strings or private
    keys in source code, prompts, logs or public documents.
[+] No default expansion into bank payment, direct bank account integration,
    QR Payment, Blockchain, group finance or enterprise finance.

J. DECISION NOTES / KNOWN CONSTRAINTS
============================================================
- Multiple chat sessions per user are required.
- User can create a new conversation and reopen previous conversations.
- Chat history is stored in PostgreSQL.
- Android request DTOs intentionally do not contain UserId.
- Proposed message roles are lowercase "user" and "assistant".
- Session list DTO expects lastMessagePreview.
- Date/time fields in Android DTOs are represented as ISO-8601 strings.
- These DTOs are a proposed API contract; Backend responses must be aligned
  with them before integration.
- The current Android build was confirmed by the user; no claim is made here
  that Backend migration/build/tests have passed.
- Master plan order is Local Infrastructure -> Admin Backend -> Admin Portal
  -> Local AI Infrastructure -> Chatbot/AI Security -> Final Testing.
  Chatbot UI preparation has been started ahead of that order as an isolated
  client-side task; this does not mean Local AI or Backend AI integration is
  already implemented.
